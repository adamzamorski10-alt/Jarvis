## 3. Final Architecture

```
UserIntent (application-controlled)
        |
        v
    AIManager.decide(intent)
        |
        v
    AIManagerProvider.decide(intent) --> RawManagerDecision (untrusted)
        |
        v
    normalize_raw_decision(raw, intent, policy)
        |
        v
    ManagerDecision (trusted) + ManagerResult
        |
        v
    Application policy / approval / execution services
```

MODEL PROPOSES. APPLICATION DECIDES. AUTHORIZED APPLICATION SERVICES EXECUTE.

## 4. Final Responsibility Boundaries

| Component | Responsibility | Authority |
|-----------|---------------|-----------|
| `UserIntent` | Application-controlled input contract | Generates `intent_id`, normalizes goal |
| `AIManagerProvider` | Translate model API to `RawManagerDecision` | Proposes decisions only |
| `AIManager` | Thin orchestration: call provider, normalize, return result | No execution authority |
| `normalize_raw_decision` | Structural + semantic validation, normalization | Rejects malformed output, enforces policy |
| `ManagerDecision` | Trusted application object | Application-controlled fields only |
| `ManagerResult` | Final outcome wrapper | outcome + optional decision + optional error |
| Application services | Policy, approval, execution, persistence | Full execution authority |

AI Manager != PlanManager != PlanExecutionService != AutonomousPlanExecutor != RunController != DevelopmentAgent != ToolExecutionService != PermissionEngine != VerificationGate.

## 9. Decision/Outcome Model

**File**: `services/core/app/ai_manager/models.py:55-68`

```python
class DecisionOutcome(str, Enum):
    REJECTED = "REJECTED"
    NEEDS_CLARIFICATION = "NEEDS_CLARIFICATION"
    NEEDS_APPROVAL = "NEEDS_APPROVAL"
    PROPOSED = "PROPOSED"
    READY_FOR_PLANNING = "READY_FOR_PLANNING"
```

- `REJECTED`: Provider/validation failure; no decision included
- `NEEDS_CLARIFICATION`: Model requires additional user input
- `NEEDS_APPROVAL`: Model proposes actions requiring approval
- `PROPOSED`: Model has proposed actions for application consideration
- `READY_FOR_PLANNING`: Model has identified a goal ready for planning

"execute now" is NOT an implicit model-controlled state. Execution authority resides entirely with application services.

class ApprovalRequirement(BaseModel):

Key invariants:
- **risk != approval**. Risk is a severity classification; approval is an authorization gate.
- Model-proposed risk does NOT override application policy. `application_policy["max_allowed_risk"]` is authoritative.
- Application policy can require approval for all actions regardless of model proposal.
- Application policy can restrict allowed capabilities.

## 12. Trust Boundary

**TRUSTED (application-controlled):**
- Application-generated IDs (`intent_id`)
- Capability definitions
- Application policy (`max_allowed_risk`, `require_approval_for_all`, `allowed_capabilities`)
- Approval decisions
- Task state, run state, workspace state
- Verification state, Git state, persistence state

**UNTRUSTED (model-derived):**
- User-derived text (`user_request`)
- Model output (`RawManagerDecision`, `RawActionProposal`)
- Model rationale
- Model-proposed capabilities
- Model-proposed arguments
- Model-proposed risk
- Model-proposed approval requirements
- Model metadata

All untrusted data is validated before entering trusted application state through:
1. Pydantic schema validation (`extra="forbid"`, bounded lengths, enum constraints)
2. Semantic validation (`_validate_no_execution_state_fields`, dependency graph validation, cycle detection)
3. Application policy enforcement (risk ceiling, capability allowlist, approval requirements)

## 13. Normalization/Validation Rules

**File**: `services/core/app/ai_manager/normalizer.py`

Validation layers (all fail-closed):

1. **Structural validation** (Pydantic):
   - `extra="forbid"` on all models rejects unknown fields
   - Enum validation for `DecisionOutcome`, `RiskLevel`
   - String length bounds on all text fields
   - Array length bounds on all list fields
   - Dict entry bounds on all dict fields

2. **Execution state injection detection**:
   - Checks `goal`, `rationale`, `warnings` for forbidden field references:
     `task_id`, `run_id`, `execution_id`, `status`, `attempt_count`, `max_attempts`, `workspace_path`, `commit_sha`, `verification_passed`, `execution_token`, `recovery_owner`, `last_heartbeat`, `execution_terminated_at`, `workspace_cleanup_pending`, `verification_gate`, `permissionengine`, `permission_engine`, `tool_execution_service`, `subprocess`, `shell`, `git`, `workspace_manager`, `run_controller`, `plan_execution_service`, `autonomous_plan_executor`, `development_agent`

3. **Action dependency validation**:
   - All dependencies must reference existing action IDs
   - No self-dependencies
   - No duplicate dependencies
   - No cyclic dependencies (Kahn's algorithm)

4. **Unique action IDs**:
   - All `action_id` values must be unique within a decision

5. **Uncertainty bounds**:
   - Must be in range [0.0, 1.0] if present

6. **Application policy enforcement**:
   - Proposed risk must not exceed `max_allowed_risk`
   - If `require_approval_for_all` is True, all actions must have `approval_required=True`
   - If `allowed_capabilities` is set, all proposed actions must have capabilities in the allowed set

7. **Type normalization**:
   - `capability_id` strings converted to `CapabilityIdentifier` objects
   - `action_id`, `action_type` validated against patterns

Malformed output fails closed. No silent repair of dangerous model output.
